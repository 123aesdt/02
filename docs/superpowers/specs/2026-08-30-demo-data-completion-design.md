# 演示数据补全设计

## 目标

在不接入企业数据、不伪造生产实时状态的前提下，为系统总览、智能体中心和运行中心补充可用于现场展示的有界虚拟数据。

## 数据规则

- 后端真实值和 WebSocket 真实事件始终优先，演示数据只填补缺失项。
- 演示快照仅在 `development_jwt` 本地演示身份或既有 `mock` 模式启用；`oidc_jwt` 模式不得回退演示数据。
- 所有虚拟内容显示“演示数据”，真实值与虚拟值共存的区域显示“混合数据”。
- 演示快照是前端展示资料，不写入 MySQL、Redis、Qdrant，不参与真实调度决策。

## 页面行为

### 系统总览

保留接口返回的运单、异常、待复核和运行线程计数。对智能体、记忆、可观测性、治理与安全四张缺少独立汇总接口的能力卡，显示统一演示摘要和“演示数据”标识；页面说明明确当前为实时计数与演示摘要的混合视图。

### 智能体中心

本地演示身份未输入真实任务 ID 时，显示固定的 `DEMO-TASK-001` 八智能体执行快照、耗时、输入和中文结果。当用户输入任务 ID 后立即退出演示快照并等待/展示该任务的真实 WebSocket 事件。

### 运行中心

保留接口返回的实时遥测值和依赖状态，只对缺失指标使用演示样本。每个补齐的指标单独标记“演示”，面板同时显示“混合数据”说明；监控完全不可用时也只能显示明确标注的演示指标，不能显示虚构的依赖健康状态。

## 验证

- 组件测试覆盖本地演示启用、OIDC 禁用、真实数据优先、真实任务 ID 抑制演示快照。
- 运行前端定向测试、完整测试、lint、build，并执行 `git diff --check`。

# CountyFlow AI 主管团队任务设计

日期：2026-08-30  
状态：已完成对话设计确认，等待书面规格复核

## 目标

为演示环境提供安全、真实、只读的主管团队任务能力。调度主管可以在主管首页查看团队摘要，并在独立页面按调度员与任务状态浏览团队任务；所有数据来自 MySQL，不使用前端静态数组或缺失接口的 Mock 回退。

## 已确认决策

- 团队范围仅包含启用且角色为 `DISPATCHER` 的演示员工。
- 第一版只读，不支持重新分配、修改状态或批量操作。
- 同时补充“调度主管台”首页摘要和独立“团队任务”页面。
- 采用独立的 `GET /api/v1/team/tasks`，不扩展或放宽 `/api/v1/my/tasks`。
- 没有演示员工数据时返回安全空集合，不把范围扩大为系统全部任务。

## 非目标

- 不接入企业组织、部门、直属关系或单点登录数据。
- 不建立通用组织架构或团队管理子系统。
- 不增加任务改派、状态变更、批准或拒绝动作；复核动作继续使用现有复核契约。
- 不改变调度员“我的任务”的本人隔离规则。
- 不为团队任务生成静态 AI 建议或推测数据。

## 后端架构

### 权限边界

新增接口依赖现有 `dispatch:review` 权限。主管和管理员可以读取；调度员、运营和审计角色返回 `403`。接口不接受请求方角色、任意团队编号或越权范围声明，团队范围完全由服务端解析。

`/api/v1/my/tasks` 保持现状：仍从已认证主体读取 `subject_id`，且只能返回该主体的任务。团队接口不复用可由客户端传入主体的“我的任务”查询，避免把本人读取和主管读取混为一个授权面。

### 团队成员来源

团队成员由 MySQL 中 `DemoEmployeeAccount` 表内满足以下条件的账号组成：

- `is_active = true`
- `role = DISPATCHER`

这是明确的演示环境定义。生产环境未配置演示员工时，接口返回零成员、零汇总和空任务页；绝不退化为查询所有 `DispatchTask`。

### 读模型

在 `workspace_reads` 模块新增专用团队读模型：

- `TeamTaskListItem`：现有员工任务安全字段，加 `assignee_subject_id` 与 `assignee_display_name`。
- `TeamTaskSummary`：`total`、`ready`、`waiting`、`active`、`ended`。
- `TeamMemberTaskSummary`：成员编号、显示姓名以及上述五项计数。
- `TeamTaskPage`：任务列表、团队汇总、成员汇总、筛选后总数、下一游标和数据来源。

API 响应使用对应的严格 Pydantic 模型，并继续禁止额外字段。

### 仓储和服务边界

`WorkspaceReadRepository` 增加窄接口 `list_team_tasks`。SQLAlchemy 仓储负责：

1. 查询启用的演示调度员成员集合。
2. 将任务范围限制为这些成员的 `assignee_subject_id`。
3. 应用可选的成员筛选和状态分组筛选。
4. 在 MySQL 中计算团队汇总、逐成员汇总、筛选后总数和游标分页。
5. 关联运单、异常及最新调度记录，返回与员工任务一致的安全业务字段。

API 处理器只负责参数校验、权限依赖、调用应用服务和响应映射，不直接导入 SQLAlchemy。应用服务沿用数字游标解析与 MySQL 连接故障规范化。

## API 契约

### 请求

`GET /api/v1/team/tasks`

可选查询参数：

- `limit`：1–100，默认 20。
- `cursor`：现有数字游标。
- `state`：`READY | WAITING | ACTIVE | ENDED`。
- `assignee_subject_id`：必须是当前服务端团队成员编号。

### 响应语义

- `items` 和响应级 `total` 受成员、状态及分页筛选影响。
- `summary` 始终表示完整团队范围，不随当前成员或状态筛选变化。
- `members` 始终返回完整团队成员及各自完整状态分布，不随任务筛选变化。
- `provenance` 依据筛选结果中的演示任务与现场创建任务计算，可为 `DEMO`、`LIVE` 或 `MIXED`。

任务项示意：

```json
{
  "row_id": 2,
  "task_id": "DEMO-TASK-002",
  "assignee_subject_id": "CF-DEMO-006",
  "assignee_display_name": "陈调度",
  "order_no": "DEMO-ORDER-002",
  "risk": "HIGH",
  "description": "乡道积水，需要安全绕行",
  "vehicle_id": "demo-vehicle-002",
  "original_route_id": "云岭乡道",
  "suggested_route_id": "国道-108",
  "status": "APPROVED",
  "created_at": "2026-08-30T08:00:00Z",
  "updated_at": "2026-08-30T08:05:00Z"
}
```

### 错误契约

- 无 `dispatch:review`：`403`。
- 无效状态或参数范围：FastAPI 标准 `422`。
- `assignee_subject_id` 不是当前团队成员：`422`，业务码 `TEAM_MEMBER_INVALID`。
- 数字游标无效：沿用 `WORKSPACE_CURSOR_INVALID`。
- MySQL 连接不可用：沿用 `WORKSPACE_READ_UNAVAILABLE` 的 `503`，不返回缓存或静态任务。

## 演示账号与任务分配

新增演示账号：

- 员工编号：`CF-DEMO-006`
- 显示姓名：`陈调度`
- 角色：`DISPATCHER`

演示种子按业务案例位置稳定分配：奇数位置归 `CF-DEMO-001` 张调度，偶数位置归 `CF-DEMO-006` 陈调度。重复执行种子时允许纠正且仅纠正 `idempotency_key` 为 `demo-seed-*` 的演示任务归属；现场创建任务及其他任务保持原归属，状态也不被重置。

种子逻辑保持幂等：不会重复创建员工、运单、异常、任务、调度、审核或运行线程。

## 前端设计

### 独立团队任务页

`/team-tasks` 从占位路由替换为真实页面，并继续受 `dispatch:review` 路由权限保护。

页面结构：

1. 团队概览：全部任务、待执行、等待中、处理中、已结束。
2. 调度员负载：张调度和陈调度的总数与状态分布。
3. 筛选：全部或指定调度员、全部或指定任务状态。
4. 任务表：任务、负责人、运单、风险、任务说明、车辆、建议路线、状态、更新时间、查看详情。
5. 游标分页：上一页、下一页；切换筛选时回到第一页。

任务详情复用现有 `/dispatch/:taskId`。页面没有重新分配、修改状态或批量操作入口。

### 调度主管台

主管首页增加“团队任务”区域：

- 使用团队接口的完整汇总展示团队任务总量与关键状态。
- 展示每名调度员的负载数量。
- 展示最近更新的 5 条团队任务。
- 提供“查看全部团队任务”链接。

现有待人工复核、运行态摘要与干预历史区域保持原职责，不把团队任务统计混入复核总数。

### 前端数据边界

新增团队任务类型、API 客户端方法和读取钩子。前端只发送已批准的筛选参数，不自行请求每名员工再拼接统计。状态、风险、来源和空态全部使用中文展示。

读取状态分别处理：

- 加载：骨架屏。
- 成功但无任务：真实零值和空列表。
- `403`：无团队任务权限。
- `422 TEAM_MEMBER_INVALID`：所选调度员已不在团队，清除筛选后允许重试。
- `503`：团队任务服务暂不可用，不回退静态数据。
- 其他错误：明确失败和重试入口。

## 测试策略

实施遵循行为级 TDD：先写失败测试并运行，再实现最小真实行为。

### 后端

- 仓储：仅包含启用的调度员任务；排除非调度员、停用账号和无归属任务。
- 仓储：成员筛选、四种状态筛选、游标分页、团队汇总和成员汇总。
- 仓储：筛选不改变完整团队和成员汇总。
- API：主管和管理员成功；调度员、运营、审计返回 `403`。
- API：无效成员返回 `422 TEAM_MEMBER_INVALID`。
- API：MySQL 不可用返回既有 `503` 契约。
- 回归：`/my/tasks` 仍使用认证主体并隔离本人任务。
- 种子：新增陈调度；演示任务奇偶稳定分配；重复执行不重复记录、不重置状态、不改现场任务。

### 前端

- 客户端：正确编码成员、状态、游标与数量筛选。
- 读取钩子：成功、空数据、`403`、`422`、`503` 和取消请求。
- 团队页面：中文汇总、成员负载、筛选、分页、负责人列和详情链接。
- 主管首页：真实汇总、最近任务和“查看全部”入口。
- 路由：主管可访问；无 `dispatch:review` 的角色不可访问且不会发起团队请求。
- 响应式：窄屏筛选和表格仍可用，不遮挡操作。

## 验收标准

- 王主管登录后在主管首页看到真实团队汇总、两名调度员负载和最近任务。
- “团队任务”页面不再显示“接口尚未开放”。
- 主管可按张调度、陈调度及四类状态筛选并进入任务详情。
- 张调度和陈调度的“我的任务”只显示各自任务。
- 非主管角色不能读取团队接口。
- 页面不展示静态团队任务、伪造零值或英文业务状态。
- 没有企业组织数据时，团队范围不会扩大到非调度员或系统全部任务。
